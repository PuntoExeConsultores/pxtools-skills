# @ExportImport Module — Data Export and Import

> Behaviour of the `@PXTools/@ExportImport` module. Module index: [20-pxtools-modules.md](../20-pxtools-modules.md).

**Location in the KB**
- Module: `Knowledge Base/@PXTools/@ExportImport` (`APIs/` core + `Personalized/`).
- Qualifier: `PXTools.ExportImport`.
- **Depends on:** `@APIs` (base).

## 1. What it provides

Generic infrastructure for **importing/exporting entities through Excel**. The module supplies the **common chassis** (upload form, cell-reading helpers, error reporting); the per-entity logic is implemented by each consumer with `Imp<Entity>`/`Exp<Entity>` procedures (generated by the `PXExportImport` pattern, outside this module). It **defines no transactions** — it operates on other people's data.

## 2. Core concept: dispatcher + per-entity hooks

- An **enum** (`PXToolsExportImportObject`) registers "what can be imported"; each application adds the value for its entity.
- Two **dispatchers** (`ChkObjects` / `ImpObjects`) run a `Do Case` over that enum and delegate to the matching `Imp<Entity>` **hook**.
- The result is an `SDTImportResult` (a collection of errors) which, if not empty, is shown in the `RepImportResult` report.

## 3. Module domains

Both belong to @ExportImport (naming: the module's real name follows `PXTools`) and are **root-legacy** (they live in the root `#Domains/`):

| Domain | Role |
|---|---|
| **PXToolsExportImportObject** (Char(50)) | Registry of "what gets imported/exported". **Extension point**: each consumer adds the value for its entity (code + description). |
| **PXToolsImportMode** (Char(20)) | `Check` (validation without persisting) / `Update` (persist). |

## 4. How it works (import flow)

1. **The `PuImport` form** (WebPanel generated by `PXParameterRequestImport`): `parm(in: &ExportImportObject, &WindowSelf)`. It presents the `&File` blob (Excel) and the `&OnlyCheck`, `&UpdateWithoutErrors`, `&DeleteSubLevelRecordsNotFound` checkboxes. The button toggles between "Check" and "Import" depending on `&OnlyCheck`.
2. **Event Enter** calls `ChkObjects.Udp(...)` (always) and, if this is not a check-only run and it either succeeded or `UpdateWithoutErrors` is set, `ImpObjects.Udp(...)`.
3. `ChkObjects`/`ImpObjects` resolve the blob to a path (`RetBlobPath`), run a `Do Case` over `&ExportImportObject` and delegate to `Imp<Entity>.Udp(&FilePath, PXToolsImportMode.Check|Update, &UpdateWithoutErrors, &DeleteSubLevelRecordsNotFound)`, which returns an `SDTImportResult`.
4. The error SDT is serialized to JSON and stored in **WebSession** (`PPEXE_AcSUV02`). `&Succeed = (&SDTImportResult.Count = 0)`.
5. If there were errors, the **`RepImportResult`** report opens (PDF, HTTP), retrieves the JSON (`PPEXE_DeSUV02`), runs `FromJson()` and prints each error (Sheet / Row / ErrorMessage). If everything went fine: "Import succeed".

### The per-entity hook contract
A consumer implements `Imp<Entity>` with:
```
parm(in: &FilePath, in: &PXToolsImportMode, in: &UpdateWithoutErrors, in: &DeleteSubLevelRecordsNotFound, out: &SDTImportResult)
```
Inside it: opens the Excel file (`&ExcelDocument.Open(&FilePath)`), iterates the rows reading cells with the `RetExcelCell*` helpers, validates (adding items to `SDTImportResult` with Sheet/Row/ErrorMessage) and, in `Update` mode (if `Count=0` or `UpdateWithoutErrors`), persists through a Business Component. To register it: add the value to the `PXToolsExportImportObject` enum and a `Case` in `ChkObjects`/`ImpObjects`.

## 5. APIs vs Personalized

- **`APIs/`** (core): `RepImportResult` (the report), the `RetExcelCell*` helpers, the `SDTImportResult` SDT, and the pattern instances.
- **`Personalized/`** (the **dispatcher**, edited to add each entity):
  | Object | What gets customized |
  |---|---|
  | `ChkObjects` (Procedure) | `Check` mode: `Do Case` on the enum → `Imp<Entity>`(Check). |
  | `ImpObjects` (Procedure) | `Update` mode: `Do Case` on the enum → `Imp<Entity>`(Update). |

## 6. Pattern instances

- **PXParameterRequestImport** — generates the `PuImport` / `PuImportSpanish` popups (blob + 3 checkboxes + the action with the conditional calls to `ChkObjects`/`ImpObjects`/`RepImportResult`).
- **PXReportTemplateRepImportResult** — applies the standard header/footer to the results report.

## 7. Key procedures / APIs

| Object | `Parm()` | Purpose |
|---|---|---|
| `RepImportResult` (Main, HTTP) | — (reads `SDTImportResult` from the session) | PDF report of import errors. |
| `RetExcelCellText` / `…Memo` / `…Short` / `…Long` / `…Date` | `(in: &ExcelDocument, &CellRow, &CellColumn; out: &Value)` | Reads a cell, normalising formulas, a trailing `.0` and scientific notation. |
| `SDTImportResult` (SDT) | `{ Sheet, Row, ErrorCode, ErrorMessage }` | The **result contract** of every import hook. |

External dependencies (`PXTools.APIs`): `RetBlobPath` (blob→path), `PPEXE_AcSUV02`/`PPEXE_DeSUV02` (WebSession — they carry the `SDTImportResult` over to the report).
