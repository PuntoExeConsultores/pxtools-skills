# @APIs Module — The PXTools Framework Base

> Behaviour of the `@PXTools/@APIs` module. Module index: [20-pxtools-modules.md](../20-pxtools-modules.md).

**Location in the KB**
- Module: `Knowledge Base/@PXTools/@APIs/`
  - `APIs/` — the **framework core** (≈420 objects). Not to be touched.
  - `Personalized/` — the **project's extension layer** (≈127 objects, 11 subfolders). This is where each application adapts the framework without touching the core.
  - `#Domains/` — the framework's base domains (4 module-scoped) + most of the framework's **base** domains live in the **root** `#Domains/` (legacy) and in `@PXTools/#Domains/` (package). See §8.
- **Depends on:** nothing inside the `APIs/` core — it is the framework's **universal base** (every module depends on @APIs). Only the `Personalized/` layer (master pages / login) references `@Menus` (PXTools) and `@ResponsiveLayout` (a **GeneXus** module, not a PXTools one).

**Framework naming conventions**
- `PPEXE_*` — helper procedures (by convention `…Ac…` = action/update, `…De…` = return/query).
- `HPEXE_*` / `H*` — web panels / master pages.
- `Pu*` / `RPu*` — popups (desktop / responsive) generated by patterns.
- `Wb*` / `Tr*` / `Ve*` — web panels generated by patterns (form / selection / view).

## 1. What it provides

`@APIs` is the framework's **base module**: it provides the **cross-cutting infrastructure** every other module and every pattern instance consumes. It models no business entity; it contributes:

- The **session context** (`Context`) and its life cycle (login → session → each request).
- The **MasterPages** (UI shells) and the responsive layout.
- The framework's **global configuration** (`PXToolsParametersSDT`).
- A large **catalogue of utility APIs** (strings, dates, files, Excel, messages, links, escaping, downloads, and so on).
- The **security connector** (authentication/authorization — see [security.md](security.md)).
- The **templates** the pattern generators use.

Every module depends on `@APIs`.

## 2. Core concept: core vs Personalized

`@APIs` embodies the PXTools extension model:

- **`APIs/`** = the generic framework. It ships with the framework; **you do not touch it**.
- **`Personalized/`** = the intended **extension points**. PXTools leaves objects there (the `Context` SDT, `PXToolsParametersSDT`, the SecurityConnector, MasterPages, Languages, Templates) **for the project to adapt**. A new project customizes `Personalized/` and consumes `APIs/`.

## 3. Session context (`Context`) — the core

The **`Context`** SDT (`Personalized/Context_Personalized/Context.StructuredDataType.gxSource`) is the logged-in user's session "backpack". It is a flat SDT (no collections), designed to be **serialized to XML** and carried in the `WebSession`. Framework fields: `SecurityUserId`, `SecurityUserCode`, `SecurityUserName`, `SecurityUserQualifiedCode` (the qualified code `user@domain`), `SecurityDomainId`/`SecurityDomainName` (tenant/domain — multi-tenancy support), `SecurityUserType` (BackOffice / FrontEnd / Invite). **Each project additionally embeds its business attributes** in this SDT (that is the customization point).

### 3.1 Context life cycle

| Proc | Location | `Parm()` | Role |
|---|---|---|---|
| `PLoadContext` | `APIs/Context_APIs/` | `out: &Context` | **Reads** the context from the `WebSession` (`&Context.FromXml(&Session.Get("context"))`). The **hydrator** every generated object and master page invokes. |
| `PSetContext` | `APIs/Context_APIs/` | `in: &Context` | **Stores** the context in the `WebSession` (`&Session.Set("context", &Context.ToXml())`). The low-level setter. |
| `PGetUserCode` | `APIs/Context_APIs/` | `out: &UserCode` | Shortcut: `PLoadContext` + return the user code. |
| `PSaveContext` | `Personalized/Context_Personalized/` | `in: &UserCode, in: &AmbienteId` | **Builds** the `&Context` from scratch: parses `user@domain`, resolves the domain, reads the users table and fills in the fields; it ends with `PSetContext`. **The customization point** for what goes into the context. |
| `PCheckContext` | `Personalized/Context_Personalized/` | `&Context, &Ok` | **Validates** the session: when `LoginSupport` is on and users exist, it returns `&Ok=False` if there is no valid session (→ redirect to login). |
| `SaveLoginContext` | `Personalized/Context_Personalized/` | `in: &UserCode, in: &AmbienteId` | The **post-login orchestrator**: builds the context (`PSaveContext`), generates the user's enabled menus, picks the main menu by `SecurityUserType` (when `SeparateMenusByUserType`), and records the WebSessionId. The login screen runs it after validating credentials. |

### 3.2 How `&Context` is injected into the generated objects

Two mechanisms combined:

1. **In every object a pattern generates**: the `&Context` variable is declared (of type `Context, PXTools.APIs`) and, at the top of `Event Start`, the `// Context Variables Initialization.` block plus `PLoadContext.Call(&Context)`. It is **ubiquitous** (hundreds of objects).
2. **In the MasterPage**: each object declares `MasterPage = 'PXTools.APIs.HMPWkWnn'`; in its `Start`/`Refresh`, the master page also calls `PLoadContext` and **resolves security** (`PCheckContext` → redirect to login on failure; `PIsAuthorized` when OK).

**The full flow:** login → `SaveLoginContext` → `PSaveContext` (built from the database) → `PSetContext` (into the session); then **on every request** → the object and its master page call `PLoadContext` (reading from the session).

## 4. MasterPages (`Personalized/MasterPages/`)

Each `HMPWkWnn` is a **shell level** matching the object's role; there is a desktop variant (Theme `PXToolsDesktop`) and a responsive one (`PXToolsResponsive`).

| Master page | Role |
|---|---|
| `HMPWkW01` | **Main** desktop (left menu, header, top menu, recent links). |
| `HMPWkW02` | **Embedded** objects. |
| `HMPWkW03` | Main for an **Embedded Data Area** (embedded lists/grids). |
| `HMPWkW04` | Main for **Transactions** (the editor). |
| `HMPWkW05` | Main for a **Transaction's Embedded Data Area**. |
| `HMPWkW06` | Main for **Prompts** (selection/lookup). |
| `HMPWkW07` / `HMPWkW08` | Embedded Data Area (inside Embedded / inside Transactions) with a Recent Link. |
| `HMPWkW09` / `HMPWkW10` | **Responsive** (main / prompts). |
| `HMPLogin` | The **login** shell (minimal: no context loading, no security — it is pre-authentication). |
| `HMPExternal` | **External/public** objects (outside the authenticated private area). |

Supporting objects: `HWCHdrDesktop`/`HWCHdrResponsive` (headers), `Publico`/`Privado` (frames), and **`RetLayoutParameters`** (the DataProvider defining the **responsive layout regions**: Container/Top/Left/Center/Right/Bottom per platform and Bootstrap dimension, with Push/Float/Smart modes and theme classes).

> **How an object picks its master page:** not at runtime — the **pattern** writes the `MasterPage = 'PXTools.APIs.HMPWkWnn'` property into the generated object's header according to its role (list / view / transaction editor / prompt / embedded / responsive).

## 5. Global configuration — `PXToolsParametersSDT`

`LoadPXToolsParameters` (`Personalized/Parameters/`) loads, per platform, the **`PXToolsParametersSDT`** SDT (`APIs/SDTs/`), the framework's **central configuration**. Generated objects and master pages consult it (through the `PPXToolsParameters` accessor, by name). Notable flags:

- **Login/security:** `LoginSupport`, `AuthenticationMode` (local / windows).
- **Menus:** `SeparateMenusByUserType` + `MainBackOffice/FrontEnd/InviteMenuName`, `LeftMenuType`, `SupportTopMenusDropDown/Tab`, `MenuIncludeSearch`, `RecentLinkLevels`.
- **UI/popups:** `PageRows`, `PopupBehaviour` + `Default/Max/Min Popup Width/Height`, `Modal…`, the `SpecialPopupWindows` collection.
- **Platforms/paths:** `SupportedPlatforms`, `ImagesPath`, `DocumentsPath`, `ExcelExtension`/`ExcelTemplateDirectory`, `ProjectNameSpace`, `SupportLogicalDelete`.

## 6. Catalogue of utility API groups (`APIs/`)

`APIs/` groups the utilities into ~50 subfolders. The main ones:

| Group | Provides | Representative procedures |
|---|---|---|
| **Classes** | Manipulating a control's CSS class string. | `AddClass(inout, in)`, `HasClass`, `ToggleClass`. |
| **Date** | ISO-8601 week numbers and a YearMonth type with arithmetic. | `DateOfWeekISO8601`, `YearMonthFromDate`, `YearMonthAddMonths`. |
| **Escape** | XML-HTML and URL encoding/escaping + XML node extraction. | `Escape` (HtmlEncode), `EncodeURLParameters`, `GetXMLNodeContent`. |
| **StringTools** | Casing, split/join, prefixes/suffixes, number→text. | `Split`, `StartsWith`, `CapitalizedCase`, `NumberToDescription`. |
| **FormState** | Persisting/restoring a web object's state in the session, by name. | `SaveFormState`, `LoadFormState`, `ClearFormState`. |
| **File / Download** | Filesystem helpers; HTTP download with MIME/Content-Disposition, retry and auto-delete. | `DelFile`, `PPEXE_SaveFile`; `DownloadFile`, the `DownloadSDT` SDT. |
| **Excel** | A framework for building Excel files from a template (Row/Col/Value/format cells). | The `ExcelTemplateData` SDT, `RetExcelElementFormat`. |
| **Message** | Queueing (in the session) and displaying messages to the user, with several front ends. | `PPEXE_Message`, `ShowMessages`, the `MessageCollection` SDT. |
| **Config** | Loading configuration (paths, classpath, WS) from an INI into a `Config` SDT. | `PLoadConfig`, `PPEXE_DeIni01`. |
| **Controller** | Navigation/flow: call type, call stack, recent links. | `PPEXE_DeCtl01`, the `ControllerCallStack` SDT. |
| **Certificate** | X.509/keystore: PFX→JKS, public key from a PEM. | `CreateKeyStoreFromPFX`, `GetPublicKeyFromPemFile`. |
| **Components / ErrorLog** | Internal naming of web components; deduplicated error logging. | `RetComponentPrefix`; `AddErrorLog`, the `SDTErrorLog` SDT. |
| **Confirm** | Reusable confirmation/message dialogs (desktop + responsive). | `HPEXE_Confirm`, `ResponsiveConfirm` (see §9). |

*(Plus: BlobTools, HTML, KB, Links, Network, Password, QRCode, Session, Tabs, Timezones, URL, Window, Zip, XMLUtil, Platform_APIs, …)*

## 7. APIs vs Personalized

### `APIs/` (core — do not touch)
The complete framework: the low-level context (`Context_APIs`), the utility catalogue (§6), the base master pages, the SDTs (`PXToolsParametersSDT`, `MessageCollection`, `DownloadSDT`, …), and the utility pattern instances (§9).

### `Personalized/` (extension points — customized per project)
| Subfolder | What gets customized | Key object(s) |
|---|---|---|
| **Context_Personalized** | The `Context` SDT and what is loaded/persisted per user (§3). | `Context`, `PSaveContext`, `PCheckContext`, `SaveLoginContext`. |
| **Parameters** | The framework's **central configuration** (§5). | `LoadPXToolsParameters`, `PXToolsParametersSDT`, `PPXToolsParameters`. |
| **SecurityConnector** | The pluggable authentication/authorization implementation (see [security.md](security.md)). | `PCheckUser`, `PIsAuthorized`, `PIsAdministrator`, `HLogin`, `PXParameterRequestLogin`. |
| **MasterPages** | The concrete shells + headers + responsive regions (§4). | `HMPWkW01-10`, `HMPLogin`, `RetLayoutParameters`. |
| **Templates** | The generator templates the patterns use for scaffolding. | `PXToolsSelection/Transaction/View/ReportTemplate`, the `PXToolsSD*Template` set. |
| **Languages** | The supported UI languages. | `RetSystemLanguages` → `SDTSystemLanguages`. |
| **Platform_Personalized** | The platforms the project targets. | `RetSuportedPlatforms` → `ApplicationPlatform` (WebDesktop, WebResponsive). |
| **System** | The system's shells: home, menu, startup, version. | `HHome`, `HMenu`, `PXToolsWebStartUp`, `PDeVer01`. |
| **Files** | File selection/upload dialogs. | `HPrFil01`, `HPrFil02`, `HPrFilEmbedded`. |
| **GridConfigurable** | The hook deciding (by object name) whether a grid is user-configurable. | `IsGridConfigurable`. |
| **Enums** | A dummy anchor forcing enumerated domains into the build. | `PXToolsEnumsDummy`. |

## 8. Module domains

@APIs is the **home of the framework's base domains**. Beyond the ones determined by use, the naming rule says **every domain prefixed `PXTools*` (the framework's namespace) or with a primitive/generic name belongs to @APIs**, regardless of how many modules use it.

**Module-scoped (`@APIs/#Domains/`) — 4:**

| Domain | Type | Values |
|---|---|---|
| **CallType** | Character(1) | Call=`C`, Return=`R`, Refresh=`F` |
| **GridHandlerColumnVisibility** | Character(5) | True=`true`, False=`false`, UserDefined=`user` |
| **GridHandlerConfigBoxAttachType** | Character(20) | ContextualBox, CreateContainer |
| **PasswordType** | Character(3) | Character=`CHR`, Numeric=`NUM` |

**Package-shared (`@PXTools/#Domains/`) — 10 (@APIs base):** `ContextualBoxItemType`, `ContextualBoxReturnData`, `DetectedDevice` (Mobile/Desktop), `ImageType` (Image/Icon), `ParametersStyle` (Positional/Named), `PositionElementCollision`, `PositionElementHorizontal`, `PositionElementVertical`, `UserControlEventAction`. *(`WhiteListReason` lives here but only @WSLayer uses it → it belongs to [wslayer.md](wslayer.md).)*

**Root-legacy base (root `#Domains/`) — the main families:**
- **Date/time:** `PXToolsDate`, `PXToolsDateTimeMinutes`, `PXToolsDateTimeSeconds`, `PXToolsDateTimeScenario`, `PXToolsYearMonth`.
- **Email/network:** `PXToolsEmail`, `PXToolsConnectionType` (SMTP/POP3), `PXToolsHttpClient`, `URLConnectionType`, `FQDN`.
- **UI/window:** `WindowType`, `WindowEnumType` (Normal/Popup/Embedded/Component/Modal), `RefreshType`, `MessageType`, `NodeType`, `SDCallType`, `TabType`, `TabCode`, `SessionVariable`, `Origin`, `ApplicationPlatform`.
- **Excel:** `ExcelDocumentValueType`, `ExcelDocumentElementType`, `ExcelTemplateType`, `ExcelDocumentElementFormatType`, `ExcelDocumentFilters*`.
- **Controller:** `ControllerCommand`, `ControllerTarget`, `ControllerExternalEvent`.
- **Description:** `DescriptionShort/Medium/Large/Maximmum/Path`, `DecimalDescriptionType`.
- **Base primitives:** `Boolean`, `MaxStr`, `MaxMem`, `MaxXML`, `MaxLnk`, `Links`, `VarLen`, `IdFirstLevel`, `IdSubLevel`, `Name`, `Error`, `ErrorDescription`, `Path`, `Version`, `AutoInc`, `Flag`, `Logico`, `Origin`, `Target`, `Move`, `Page`, `SortOrder`, `OrderLarge`, `ObjectDescription`, `Objetos`, `Language`, `LanguagePlatform`, `AuthenticationMode`, `OperatingSystem`, `CPUType`.
- **Shared base contracts:** `TaskManagerExecutionResponse`… **no** — that one belongs to [@TaskManager](taskmanager.md); but `SDTCounterType` (Failed/Succeed), `NotificationMethod`, `SMSParameterDeliverStatus`, `PXToolsCharLengths` and `PXToolsModules` (the namespace registry) do.

> A domain named after another module (`SystemParameter*`, `Security*`, `DynamicCallReference*`, `TaskManager*`…) does **not** belong to @APIs even when @APIs consumes it: it is documented in its owning module.

## 9. The module's pattern instances

| Instance | Type | What it is |
|---|---|---|
| **PXParameterRequestConfirm** | ParameterRequest (popup) | A **generic Yes/No confirmation popup**. It receives `&ConfirmText`, displays it, and returns the boolean to the caller through the `ConfirmResponse` session variable. It generates `PuConfirm` (desktop) and `RPuConfirm` (responsive). |
| **PXWorkWithMessages** | WorkWith (popup) | A window loading the queued messages (`PLoadMessages`), showing them in a grid and clearing the queue. |
| **PXParameterRequestEncodeUrl** | ParameterRequest | A utility: it takes a URL, calls `EncodeURLParameters` and shows the escaped result. |
| **PXParameterRequestNumberToDescription** | ParameterRequest | A demo of the `NumberToDescription` procedure (number → text in words). |
| **PXParameterRequestLogin** | ParameterRequest (login page) | The **login screen** (user/password + environment): it validates credentials/access, resolves the platform, saves the context and redirects to the menu. It generates `WbLogin`. Heavily customized per project. See [security.md](security.md). |

## 10. The most frequently invoked public helpers (`PXTools.APIs`)

| Helper | `Parm()` | Purpose |
|---|---|---|
| `PPEXE_Message` | `in: &Message` | Queues a message (in the session) for later display. Ubiquitous, even in batch/WS code. |
| `ShowMessages` | — (reads the session) | Drains the queue: loads it, clears it and emits each message with `Msg()`. |
| `PSetMessages` / `PLoadMessages` / `PClearMessages` | `MessageCollection` | Persist / read / clear the message queue in the session. |
| `PPEXE_Link` | `&Link` | A **platform-aware** redirector: navigates the current program to the link (desktop vs responsive). |
| `PPEXE_Return` | `in: &WindowType` | Client-side return/close script handing a popup back to its caller. |
| `PPEXE_Refresh` | `in: &WindowSelf` | Refreshes the caller window client-side. |
| `PPEXE_Run` | `in: &PathAndFile, in: &Params, in: &WorkingDir` | Runs an external OS process/command (C#/Java backends). |
| `DownloadFile` | — (HTTP, reads a `DownloadSDT` from the session) | Streams a file from the server to the browser with Content-Type/Disposition + delete-after-download. |
| `EncodeURLParameters` / `DecodeURLParameters` / `Escape` / `UnEscape` | `in, out` | URL / HTML encoding. |
| `PuConfirm` (`APIs/Confirm/`) | `in: &ConfirmText, &WindowSelf` | The confirmation popup (§9). It is **opened as a modal window** and the answer is read from the `ConfirmResponse` session variable (not through a direct `.Call`). |
| `NumberToDescription` | `in: &Language, &Number, &DecimalDescriptionType, &MainInvoque, out: &Description` | Number → text in words. |

## 11. Integration: how the application consumes it

- **Context:** every UI object calls `PLoadContext.Call(&Context)` in its Start (the pattern injects it); the `&Context` yields the user, the domain/tenant and the business data the project embedded in the `Context` SDT (§3).
- **Confirmations:** for an "Are you sure?", open `PuConfirm` (or go through `HPEXE_Confirm`) and read `ConfirmResponse`. The patterns expose this as an action's `confirm` attribute.
- **Messages:** queue with `PPEXE_Message` and display with `ShowMessages`.
- **Navigation/downloads:** `PPEXE_Link`/`PPEXE_Return`/`PPEXE_Refresh` for the flow between screens and popups; `DownloadFile` + `DownloadSDT` for exporting files.
- **Configuration/platform:** consult `PXToolsParametersSDT` (through `PPXToolsParameters`) for global flags; the master pages and the responsive layout come from `Personalized/MasterPages/`.
